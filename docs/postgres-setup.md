# AMOS 本地 PostgreSQL 搭建与 Flyway 说明

本文说明如何在本机用容器化 PostgreSQL 跑 AMOS 后端，以及数据库脚本的组织方式。

## 1. 数据库脚本组织原则

AMOS **只用 Flyway 作为唯一的业务表结构来源**，H2 与 PostgreSQL 跑同一套迁移：

| 类别 | 位置 | 由谁执行 | 内容 |
|------|------|----------|------|
| 数据库初始化 | `scripts/postgres/00_create_database.sql` | 手动执行一次 | 仅 `CREATE DATABASE` / `CREATE USER` / 授权，**不含业务表** |
| 业务迁移 | `amos-app/src/main/resources/db/migration/V*__*.sql` | Flyway 自动 | 建表 / 约束 / 索引 / 种子数据，**H2 与 PG 共用** |
| 本地说明 | `docs/postgres-setup.md` | —— | 本文 |

> 不要维护 `schema-postgres.sql` 与 `schema-h2.sql` 两套；不要靠 `ddl-auto: update`；不要从 GUI 手工建业务表。

## 2. 启动本地 PostgreSQL（OrbStack 容器）

容器配置见 `~/postgres-local/docker-compose.yml`（不在本仓库内，属本机环境）。

```bash
# 启动容器（首次会拉取 postgres:17 镜像）
docker compose -f ~/postgres-local/docker-compose.yml up -d
```

连接信息：`host=localhost` `port=5432` `user=postgres` `password=postgres`。

## 3. 创建业务库与账号（仅首次）

```bash
docker compose -f ~/postgres-local/docker-compose.yml exec -T db \
  psql -U postgres -d postgres -f /dev/stdin < scripts/postgres/00_create_database.sql
```

脚本会创建：
- 业务库 `amos`
- 应用账号 `amos_app`（密码 `amos_app`，仅本地开发用）
- 相应授权

> `application.yml` 的 `postgres` profile 当前仍用 `postgres` 超级用户连接；如需改用 `amos_app`，
> 把 profile 里的 `username`/`password` 改为 `amos_app` 即可。

## 4. 启动后端（自动执行 Flyway）

AMOS 要求 **JDK 17**（Spring Boot 3.2.5）。本机可用 Temurin 17：

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home
cd amos-server/amos-app
mvn spring-boot:run        # postgres 已是默认 profile
```

启动时会自动：
1. Hikari 连接 `jdbc:postgresql://localhost:5432/amos`
2. Flyway 扫描 `db/migration/*` 并执行尚未应用的迁移
3. 在 `amos` 库建表（`flyway_schema_history` 记录版本）

## 5. 验证 Flyway 是否成功

```bash
# 看应用日志
grep -iE "Flyway|HikariPool|jdbc:postgresql" /tmp/amos_run.log

# 直接查库里的表与迁移历史
docker compose -f ~/postgres-local/docker-compose.yml exec -T db \
  psql -U postgres -d amos -c "select version, description, success from flyway_schema_history order by version;"
```

期望看到 `V1`、`V2` … 均为 `success = true`，且 `information_schema.tables` 中出现对应业务表。

## 6. 新增业务表的约定（H2 / PG 双兼容）

- 文件名：`V{n}__{描述}.sql`，版本号递增（当前已有 `V1`、`V2`）。
- **所有迁移（含 `V1`）一律用双兼容写法**：`BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` 代替 `bigserial`；
  数值用 `DOUBLE PRECISION` / `NUMERIC`；布尔用 `BOOLEAN`；文本用 `VARCHAR` / `TEXT`。
  > 说明：`V1__init.sql` 最初用了 PG 专有的 `bigserial`，已统一改为 `IDENTITY` 写法，
  > 因此同一套迁移在 H2（`MODE=PostgreSQL`）与 PostgreSQL 上都能成功执行（已实测双跑通过）。
- 避免 PG 专有语法（`DO $$ ... $$`、`serial`、`gen_random_uuid()` 等）以免 H2 失败；
  若确需 PG 专有特性，请单独评估并在注释中标注仅 PG 适用。
- 种子数据放对应迁移内，注意可重复执行（用 `WHERE NOT EXISTS` 或幂等写法）。

## 7. 用 H2 验证双跑（快速测试 / 演示）

H2（`MODE=PostgreSQL`）与 PostgreSQL 跑同一套 `db/migration` 迁移，适合无本地 PG 时快速验证脚本或做演示启动。

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home
cd amos-server/amos-app
# 覆盖默认的 postgres profile，改用内置 H2（内存库，随 JVM 关闭释放）
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.profiles.active=default --server.port=8081"
```

验证要点：日志中出现 `Successfully applied N migrations ... now at version vN`，且 `GET /actuator/health` 返回 200，
即说明该套迁移在 H2 上也能跑通，与 PostgreSQL 同源。
